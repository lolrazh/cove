## User Intention
Section 5j of `ARC-PARITY.md`: Arc's Boosts. Per-site custom CSS and
optionally JavaScript, toggleable and persisted, with Arc-like simple
controls (a color tint, a font, hidden elements) above a code section, an
editor opened from site controls and the Command Bar, and Zap mode: click
elements on the page to hide them. Ran in parallel with 5e (Spaces) and 5f
(Peek, Little Arc, Split View), so the `TabSession` hook is one line.

## What We Accomplished

### Model and store
- ✅ **`Boost`**: a `Site` domain, `includesSubdomains` (on by default),
  `isEnabled`, `tint` ("#RRGGBB"), `font` (System, Rounded, New York, Avenir
  Next, Monospaced), `hiddenElements` (selectors), `css`, `script`.
  `covers(_:)` ignores on/off, `applies(to:)` doesn't. `stylesheet` puts the
  simple controls first and the user's CSS last; each hidden selector is its
  own rule, so one bad selector can't void the others. Several Boosts can
  cover a page (example.com and news.example.com): `[Boost].applying(to:)`
  orders a parent site's first, so the subdomain's wins.
- ✅ **`BoostStore`**: `[Boost]` as pretty-printed, key-sorted JSON in
  `Application Support/Cove/boosts.json`, which is already an export format
  and a sync payload. Saves replace in place; a Boost that changes nothing
  is removed, so opening the editor and closing it leaves nothing. Writes
  happen at once (a few KB, even per keystroke). `boost(for:)` finds the
  site's own Boost or the nearest one covering it, for the editor.

### Applying
- ✅ **`BoostInjector`** (in `TabSessionServices.boosts`). One call in
  `TabSession`, next to the content-blocking exceptions: as each main-frame
  navigation is decided it gives the web view the user scripts for the page
  it's about to load. So a same-tab navigation to another site drops them
  and coming back adds them again.
- ✅ **Why per navigation, not one script checking `location`**: user
  scripts belong to a web view, and the alternative would put every site's
  Boost code (and its domain) into every page. It also matches content
  blocking's exceptions.
- ✅ A controller can only remove all its user scripts (the per-world
  removal is private API), so the injector keeps the ones it added and puts
  the others (link hover, form input, media) back.
- ✅ **CSS** is a `<style id="cove-boost">` added at document start and
  moved to the end of the head at `DOMContentLoaded`, so it wins ties with
  the page's styles. When Boosts change, open pages get the new sheet at
  once via `callAsyncJavaScript` (live preview, live toggle).
- ✅ **JavaScript** runs at document end, each Boost in an async function of
  its own (no clashing declarations, top-level `await` works), and only on
  the next load: the editor has Reload, and turning a Boost with a script
  on or off reloads.
- ✅ **Content world**: everything runs in `WKContentWorld.world(name:
  "Boosts")`, as Arc's Boosts ran as an extension's content scripts. Scripts
  share the DOM, which is what nearly every Boost changes, but not the
  page's JavaScript: the page can't see or tamper with them, and they can't
  read its variables. A Boost that needs the page's world can add a
  `<script>` element (subject to the page's CSP). Chosen over the page world
  deliberately; documented on the type.
- ✅ **Tint**: two fixed washes on `html::before/::after` that let clicks
  through, a `color` blend (60%) for the hue and a faint `multiply` (12%) for
  whites. A page with no background of its own (html and body transparent)
  has nothing to blend with and showed the tint at full strength, so the
  style script marks such pages and the tint gives them the `Canvas` color.
- ✅ **Font**: `font-family` on everything under body except code, icons
  (`[class*=icon i]`, `[class*=symbol i]`, `i`) and SVG.

### Zap mode
- ✅ **`BoostZap`**: a script evaluated in the Boosts world outlines the
  element under the pointer (a fixed overlay, crosshair cursor), swallows
  pointer and mouse events so links don't fire, and posts a selector on
  click. Escape (the web view is made first responder when zapping starts)
  or leaving the page ends it; the editor's Done Zapping and Escape in the
  editor end it too. The message handler is added for the session and
  removed after.
- ✅ **Selectors** aim to survive a reload: a stable id, else `data-testid`,
  else the shortest path of tags and up to three classes, made unique with
  `:nth-of-type` only where needed. Ids and classes with three or more
  digits in a row look generated and are skipped. A path of bare tags
  alone (`span`) could match what a page adds later, so it must contain an
  id, test id or class, or start at `body`.
- ✅ Each zapped element is a row in the editor with Show Again.

### Editor
- ✅ **`BoostEditorPanel`**, floating at the page's top-trailing edge like
  the find bar (the page stays usable beside it, which zapping needs): the
  domain and an on/off switch; Include subdomains; Color (none, six
  swatches, a color well); Font (The Site's Own or one of five); Hidden
  Elements with Zap Elements; Code (folded) with CSS and JavaScript
  editors and Reload; Delete Boost. As tall as its content, scrolling when
  the page is shorter. Escape stops zapping, else closes.
- ✅ **`CodeEditor`**: an `NSTextView` representable, monospaced, with undo,
  smart quotes/dashes, replacement, spelling and link detection off.
- ✅ **`BoostEditor`** (model): edits save as they're made; it's tied to the
  tab it opened on (`TabManager.boostEditor`); switching tabs hides it and
  stops zapping.
- ✅ **Site controls**: a Boost row: "Boost This Site" for a site without
  one, else Edit and an on/off switch.
- ✅ **Command Bar**: "Boost This Site" (keywords css, javascript, zap,
  hide, theme, font, color...).

### Private windows
- ✅ Boosts apply in private windows (they're global, as in Arc), but they
  can't be made or edited there: no Boost row in site controls, no
  command. Like pins, a Boost writes a site's name to disk, which a private
  window promises not to do. (`TabManager.canBoost`.)

### Tests
- ✅ `BoostTests`: host matching (www, subdomains on/off, other sites,
  hostless pages, off), ordering of several Boosts, the stylesheet's order,
  emptiness, the store's round trip, in-place saves, removing emptied
  Boosts, which Boost the editor opens.
- ✅ `BoostPageTests` (a real `WKWebView`): a Boost hides an element on its
  site, then follows a change live (unhide + new CSS) without a reload;
  another site's page goes without; zap selectors for an id, a class plus
  `:nth-of-type`, a test id, and a generated id (falls back to a path from
  `body`) each match exactly one element.

## Key Learnings
- `WKUserContentController` has no public way to remove one world's user
  scripts; keep your own and re-add the rest.
- A `mix-blend-mode` overlay on a page without a background blends with
  nothing and shows at full strength; the web view's white isn't backdrop.
- macOS `DisclosureGroup` only toggles from its chevron.
- `filter` would have recolored the whole page without a backdrop, but it
  rotates every hue rather than tinting.

## Deferred
- No export/import UI or list of all Boosts yet (the JSON is ready for
  both, and for sync).
- The Command Bar ranks "Boost This Site" below the search row for the
  query "boost"; that's the ranker's general command weighting, as noted
  for Site Settings.
- Boosts apply to the main frame only; zapping inside iframes isn't
  possible.
- Pages that add styles late (CSS-in-JS) can override Boost CSS in ties;
  `!important` wins.
