## User Intention
Section 5k of `ARC-PARITY.md` (PRODUCT.md Phase 3): run Chrome/Firefox/Safari
extensions in Cove. Install unpacked folders and archives, list them in
Settings with enable/disable, permissions, private-window access and remove;
persist them and their grants; one `WKWebExtensionController` per profile,
attached at the single web view path; private windows off unless allowed;
`WKWebExtensionTab`/`WKWebExtensionWindow` adapters instead of polluting
`TabSession`; delegate methods for tabs, windows, permission prompts and
popups; buttons in the sidebar header and navigation bar with badges and
overflow; Command Bar entries; a test extension; a real MV3 extension.

The PRODUCT.md plan (JavaScriptCore runtime, our own `tabs`/`storage` APIs)
predates WebKit's public WebExtensions API (macOS 15.4+). Cove targets 26, so
it uses that API: WebKit runs background service workers, content scripts,
`declarativeNetRequest`, storage and messaging; Cove supplies windows, tabs,
UI and policy. Verified against the macOS 27 SDK headers and the WebKit Swift
overlay (`didCloseTab(_:windowIsClosing:)` etc. are refined for Swift).

## What We Accomplished

### Library (`Extensions/InstalledExtension.swift`, `ExtensionLibrary.swift`)
- ✅ **`InstalledExtension`**: id, file name, name at install, enabled,
  `allowsPrivateBrowsing` (off by default), and `granted`/`denied`
  **`ExtensionGrants`** (permission names and match-pattern strings, each with
  its expiry, the same shape as the context's dictionaries). `allow(permission:)`
  / `allow(site:)` move an entry between the lists. Bridging to WebKit types
  drops patterns WebKit can't parse.
- ✅ **`ExtensionLibrary`** (one per app, `Application Support/Cove/Extensions/`
  with `Extensions.plist`, read through `StoreFile`). `prepare(from:)` copies a
  folder, or a zip/.xpi as `<id>.zip` (WebKit loads zips directly), and reads
  it with `WKWebExtension(resourceBaseURL:)`; `install` grants what the
  manifest asks for (permissions and all requested match patterns, content
  scripts' included), since the user just reviewed that list; `discard` and
  `remove` delete files. `loadInstalled()` runs at launch and sweeps files
  nothing refers to. It also brokers `windows.create`: the app hands it an
  `openBrowserWindow` closure (through `ExternalURLRouter`) and the next window
  to appear is returned to the extension.

### Hosts, one per profile (`Extensions/ExtensionHost.swift`)
- ✅ `BrowsingContext` gains `extensions: ExtensionHost`, made with the
  context: the default profile uses `WKWebExtensionController.Configuration
  .default()`, other profiles `Configuration(identifier: profileID)`, each with
  the profile's data store, so extension storage is per profile like cookies.
  A private window's context **shares its base profile's host**; its
  `ExtensionWindow` reports `isPrivate`, and WebKit keeps it from extensions
  without `hasAccessToPrivateData` (the per-extension toggle).
- ✅ The host follows the library (`$installed` + `$extensions`): starts a
  context per enabled extension with a fixed `uniqueIdentifier` (the record's
  UUID) and `baseURL` (`webkit-extension://<uuid>/`) so storage survives
  relaunches, stops the rest, applies grants and private access, and removes
  data records of extensions no longer installed (also catching ones removed
  while a profile wasn't open). Grant changes made by WebKit (prompts,
  `permissions.request/remove`) come back through the context's eight
  permission notifications and are written to the library, which pushes them
  to every profile; a flag ignores the notifications our own writes cause.
- ✅ **Single web view path**: `WebKitEnvironment.makeWebView(in:for:)`
  attaches the host's controller to every configuration. An extension's own
  page (options page, `tabs.create` with `runtime.getURL`) needs a web view
  made from that context's `webViewConfiguration`; `BrowserWebView
  .extensionPage` tags it, and `TabSession.webView(loading:)` swaps the web
  view when a load crosses between an extension's pages and the web (also from
  link clicks, in `decidePolicyFor`). `wake()` builds for the tab's URL.
  Extension pages aren't recorded in history; the URL pill shows the
  extension's name instead of its UUID host.
- ✅ Delegate: open windows (focused first) and focused window; `openNewTab`
  (into the asked-for window or the focused one, beside the parent, selected
  only if asked); `openNewWindow` (private or not); permission prompts for
  permissions, URLs and match patterns; `didUpdate action` (refreshes
  buttons); `presentActionPopup` (shows `action.popupPopover`). Options pages
  use WebKit's default, which opens a tab through `openNewTab`.
- ✅ Extension keyboard shortcuts (`commands`, including `_execute_action`):
  `BrowserWebView.performKeyEquivalent` offers the event to the controller's
  contexts after the menu bar's ⌃ shortcuts.

### Windows and tabs (`ExtensionWindow.swift`, `ExtensionTab.swift`, `TabManager+Extensions.swift`)
- ✅ **`ExtensionWindow`** (owned by `TabManager`, `track(self)` in init,
  `attach`/`close` from `BrowserView`): the tabs of the space shown
  (Favorites, Pinned, Today) in display order and the active tab. It diffs the
  `TabManager`'s published lists on the next main-queue turn and reports
  `didOpenTab`, `didCloseTab`, `didActivateTab`; focus from
  `didBecomeKeyNotification`; closing reports every tab with
  `windowIsClosing`. Switching to a space of another profile moves the window
  from one host to the other. Window state, frame, focus and close map to
  `NSWindow`. It also holds popup anchors.
- ✅ **`ExtensionTab`**: a stand-in per `TabSession` reporting URL, title,
  loading, muted, audio and pinned changes; answers title/URL/pinned/muted/
  selected and acts through the tab (navigate, reload, back/forward, select,
  duplicate, close, mute, pin). A sleeping tab offers no web view.
  `shouldGrantPermissionsOnUserGesture` is on, so `activeTab` works from a click.
- ✅ `TabManager+Extensions`: `extensionHost` (the active space's profile's),
  `extensionContexts` (filtered to private-allowed in private windows),
  `performExtensionAction`, `openOptions`, `openTab(url:nextTo:selected:)`.
  `TabManager` itself gets one stored property and one line in `init`.

### Permission sheet (`ExtensionPermissions.swift`)
- ✅ `ExtensionPermissionRequest` turns permissions and sites into plain
  lines (pure, tested): sites first ("Read and change your data on all
  websites", or by host, "a.com, b.com and 2 other sites"), then only the
  permissions that reach beyond the extension (tabs, cookies, webNavigation,
  webRequest, DNR, clipboard, native messaging), as Chrome does.
- ✅ `ExtensionPermissionSheet`: icon, "Add “Name”?" / "“Name” would like
  to", the lines in a rounded box, Cancel/Add Extension or Don't Allow/Allow.
  Used as the install review (SwiftUI sheet in Settings) and, through
  `ExtensionPermissionPrompt`, as an `NSWindow` sheet on the tab's window for
  runtime requests.

### Buttons (`ExtensionToolbar.swift`)
- ✅ `ExtensionToolbar` at the end of the sidebar header row and before the

## Key Learnings
- **`WKWebExtension.Action` is one object that mutates.** Passing it to a
  child view hides its changes from SwiftUI's diff; snapshot the values.
- **Anchor `NSView`s under SwiftUI report odd `visibleRect`s** (no clipping);
  test the view's rect in window coordinates against the window's bounds.
- **A `ViewThatFits` whose last candidate doesn't fit still shows it**, so a
  toolbar that must never overflow needs an empty last candidate.
- **The sidebar header has no spare room at 240pt**: the traffic lights and
  four controls take ~214 of it.
- WebKit injects content scripts into already-open pages when a context loads,
  and removes extension storage with `removeData(ofTypes:from:)` on records
  found by `uniqueIdentifier`.
- The settings toolbar and disclosure triangles don't respond to AX `click`;
  mouse clicks do. The harness's `mouse` aims at the frontmost tall window,
  which can be a popover; an absolute clicker was needed. Another agent's Cove
  window can cover yours: capture by window ID.

## Decisions for the coordinator
- **Grants are global, storage is per profile.** What an extension may do is
  the user's decision about the extension; its `storage` follows the profile,
  like cookies. Enabling/removing applies everywhere.
- **Private windows share the profile's host** and see only extensions with
  Allow in Private Windows; their `storage` is shared with normal windows.
- **Adding grants everything the manifest asks for** after the review sheet
  (Chrome's model), including content-script sites; optional permissions are
  asked for at runtime. Each can be switched off in Settings.
- **Extensions copy into Application Support**, so "Load Unpacked" is a
  snapshot, not live-reloading of a developer folder.
- **The header shows buttons only when there's room**; at the default width
  they live in the site controls' shelf and the Command Bar. Widening the
  sidebar shows them. Changing the default sidebar width was out of scope.
- `.xpi` is loaded as a zip; WebKit reads it if the manifest suits WebKit
  (Firefox-only keys are reported as manifest errors, not fatal).

## Not supported by WebKit's API, or left out
- **Chrome Web Store / AMO installs**: no API; `.crx` (signed header) isn't
  read. Install from a folder or zip.
- **Native messaging** (`runtime.sendNativeMessage`/`connectNative`): the
  delegate methods exist but Cove has no app-extension host to talk to; not
  implemented (password managers like Bitwarden's desktop integration won't
  connect).
- **`webRequest` blocking** isn't in WebKit (MV3 DNR is). `history`,
  `bookmarks`, `downloads`, `management`, `notifications` APIs aren't
  provided by WebKit's API.
- **Context menus** (`contextMenus`/`menus`, `context.menuItems(for:)` and
  action `menuItems`) aren't shown yet; the page's menu would need the tab
  from `BrowserWebView`.
- **New-tab overrides** (`chrome_url_overrides.newtab`) are ignored.
- `tabs.move`/`didMoveTab`, multi-tab selection, reader mode, tab groups,
  `setParentTab` and webpage locale detection aren't reported/implemented.
- Little Cove and Peek tabs run content scripts (their web views carry the
  controller) but aren't reported to extensions as tabs.
- `windows.create` for a non-default profile opens a window on the first
  space, as ⌘N does.
