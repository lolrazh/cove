## User Intention
Section 5b of `ARC-PARITY.md`: find in page, zoom remembered per site, print,
Save Page As, View Source, and Picture in Picture, each in the menus and the
Command Bar. Run in parallel with 5a (tab basics) and 5c (tab sleeping), so
edits to shared files stay small.

## What We Accomplished

### Layout of the change
- Page commands live in two extensions, `TabManager+PageTools.swift` (the
  entry points the menus and the Command Bar call, plus toasts) and
  `TabSession+PageTools.swift` (what the web view does), and one `Commands`
  struct, `PageToolsCommands`, added beside `BrowserViewCommands` in
  `CoveApp`. Shared files get a few lines each: the zoom store in
  `TabSessionServices`, `findInPage` and `pageZoom` on `TabSession`, a
  `didCommit` delegate method, the find bar overlay in `BrowserShellView`,
  and the Command Bar cases.

### Find in page
- ✅ **`FindInPage`**, one per tab (lazy on `TabSession`, following the web
  view when it's replaced): `isPresented`, `query`, `isFound`, and a
  `focusRequests` counter so ⌘F refocuses a bar that's already up.
- ✅ **`FindBar`**: a compact bar floating top-trailing in the page card, on
  `chromeFloatingSurface` like the revealed sidebar, with the
  `chromeFieldStyle` field, previous/next/close accessory buttons, and
  "Not Found" when the page has no match. Scales in from its corner with
  `ChromeMotion.commandBar`, fades under Reduce Motion. Return and ⇧Return
  step through matches, Escape closes and hands focus back to the page. Not
  shown on a start page. It sits in the page `ZStack`'s overlays, so it works
  in all four tab modes and stays under the top-mode toolbar.
- ✅ **Edit › Find**: Find on Page… ⌘F, Find Next ⌘G, Find Previous ⌘⇧G. In a
  window without a `TabManager` (View Source) they send
  `performTextFinderAction(_:)` instead, so the text view's own find bar
  answers ⌘F there.
- ✅ Typing a longer query used to skip the match it extended: WebKit searches
  on from the end of the selection. The selection is collapsed to its start
  (client world) before each new query.
- **No match count.** `WKWebView.find(_:configuration:)` returns only
  `matchFound`. WebKit's count lives behind its `NSTextFinder` client
  methods (`findMatchesForString:…`), which only AppKit's own find bar can
  drive; counting in JavaScript would disagree with WebKit's matching. Left
  out rather than hacked.

### Zoom
- ✅ **`PageZoom`**: Safari's steps (50–300%), `zoomedIn(from:)` /
  `zoomedOut(from:)`, which snap a between-steps zoom to the next step.
- ✅ **`SiteZoomStore`** (`AppServices.siteZoom`): host → zoom in
  `UserDefaults` (`browser.siteZoom`); 100% is removed, not stored.
  `TabSession.pageZoom` sets the web view and remembers it; `didCommit`
  applies the site's zoom to every committed navigation, restored tabs
  included.
- ✅ View › Actual Size ⌘0, Zoom In ⌘+ (⌘= works too), Zoom Out ⌘−; a toast
  shows the level ("Zoom 125%").

### Print, save, source
- ✅ **Print…** ⌘P (File): `printOperation(with:)` as a sheet. Needed the
  `com.apple.security.print` entitlement: without it the sandbox shows "This
  application does not support printing". The print view gets the web
  view's bounds, or WebKit prints blank pages.
- ✅ **Save Page As…** ⌥⌘S (File; ⌘S belongs to the sidebar in 5a):
  `SavePagePanel`, a save sheet with a Format menu like Safari's, Web Archive
  (`createWebArchiveData`) or Page Source. Switching formats swaps the
  extension.
- ✅ **`WebArchive.mainResource(in:)`** reads the archive's main resource: the
  HTML exactly as the server sent it, with its declared text encoding. Page
  Source saves those bytes; View Source decodes them. No refetch, so no
  cookie or POST problems, and it's the original source, not the scripted
  DOM.
- ✅ **View Source** ⌥⌘U (View): `SourceWindow`, a read-only monospaced
  `NSTextView` in its own window (subtitle: the page URL) with the system
  find bar. Chose a window over a tab: a source tab would have to fake a URL,
  be saved in the session and survive navigation.

### Picture in Picture
- ✅ View › Picture in Picture and the Command Bar run a script in WebKit's
  client world: exit if a video is already in PiP; otherwise the playing
  video, or else the largest, gets `requestPictureInPicture()`. "No Video on
  This Page" toast when there's none. `evaluateJavaScript` counts as a user
  gesture, which the API requires.
- ✅ **macOS web views have Picture in Picture off.** The request failed with
  "NotSupportedError: The video element does not support the
  Picture-in-Picture mode", and the native video controls had no PiP button.
  `WebKitEnvironment` now sets the `allowsPictureInPictureMediaPlayback`
  preference through KVC, the same way it already enables
  `developerExtrasEnabled`; there's no public switch on macOS. Pages' own
  PiP buttons work now too.

### Fixed along the way
- ✅ Opening a video or audio file directly (`…/movie.mp4`) showed "Can't Open
  This Page: Plug-in handled load". That's WebKit's error 204, reported when
  its media player takes over the load; it now counts as a cancellation, like
  102 for downloads.

### Command Bar
- ✅ Find on Page, Zoom In, Zoom Out, Actual Size, Print, Save Page As, View
  Source, Picture in Picture, offered only on web pages; zoom commands only
  when they'd change something.

### Tests
- ✅ `PageZoomTests` (steps, snapping, ends, the store forgetting 100%) and
  `WebArchiveTests` (declared encoding, UTF-8 default, non-archives).

## Key Learnings
- Sibling agents' Cove builds and the user's apps fight for focus. Keys
  posted to a PID (`CGEvent.postToPid`) don't reach the sandboxed save
  panel, which runs out of process; System Events keystrokes do, after a
  frontmost check. Menu clicks through System Events are the most reliable
  trigger, retried until the app is frontmost.
- `NSLog` from the sandboxed app didn't surface in `log show`; a debug toast
  was the quickest probe.
