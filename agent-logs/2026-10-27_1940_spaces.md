## User Intention
Section 5e of `ARC-PARITY.md`: Arc's spaces (a name, an icon, a theme, their
own Pinned and Today, Favorites shared), switching by footer dots, a
two-finger swipe with paging, ⌃1–9 and ⌘⌥←/→, a sensible top-tab mode, and
profiles that keep cookies and logins apart through
`WKWebsiteDataStore(forIdentifier:)`, built on 5i's `BrowsingContext`.
Private windows stay without spaces. Air Traffic Control was in scope at
first and then dropped by the user; none of it was built. Ran beside 5f
(Peek/Split) and 5j (Boosts); rebased onto Boosts (#14).

## What We Accomplished

### Model (`Spaces/Space.swift`, `SpaceStore.swift`; tested)
- ✅ **`Space`**: id, name, `SpaceIcon` (`.symbol` or `.emoji`), a
  `ChromeTheme` (now `Codable` and `Hashable`) and a profile ID. **`Profile`**:
  id and name. Both defaults have fixed IDs, so data from before Spaces
  lands in the first space and the default profile without a lookup.
- ✅ **`Spaces`** is pure: at least one space, always the default profile.
  `addSpace(in:)` names "Space N" and picks the first preset theme no other
  space wears; `update` keeps a name and a known profile; `removeSpace`
  never removes the last; `moveSpace(by:)` and `moveSpaces(fromOffsets:)`;
  `space(_:from:)` gives neighbors without wrapping (swiping past the last
  space goes nowhere, as in Arc); `removeProfile` moves its spaces to the
  default profile.
- ✅ **`SpaceStore`** (one per app, `spaces.plist`): `change { }` publishes
  and saves once. It also hands out each profile's `BrowsingContext`, made on
  first use (`context(for:)`), and `deleteProfile` removes the profile, then
  its data (`removeData` for every type, then `remove(forIdentifier:)`).
  WebKit can still hold the store at that moment, so
  `removeOrphanedDataStores()` sweeps identifiers no profile owns at launch.
- ✅ **`BrowsingContext.profile(_:faviconStore:)`**: a persistent
  `WKWebsiteDataStore(forIdentifier:)`. Favicons stay shared (they say which
  sites were seen, not who was signed in); site permissions are per context,
  so per profile. `TabSessionServices.with(_:)` swaps the context.
- ✅ The first launch takes the old frame color (`browser.themeColor`, now
  `legacyThemeColor`) as the first space's theme; the global theme setting
  and the Appearance swatches are gone, since every space carries its own.

### Pins (`PinLayout`, `PinScope`)
- ✅ **`PinLayout`** holds Favorites by profile and Pinned by space;
  `layout[scope]` reads and writes one space's `Pins`, so all of 5d's moves
  work unchanged. Empty sections aren't kept, so an edit that changes
  nothing compares equal and isn't published. `update(_:)` renames a pin
  wherever it is (a background space's tab recording its title);
  `prune(to:)` drops a deleted space's Pinned and moves a deleted profile's
  Favorites to the default profile. `AppServices` prunes on every spaces
  change, wherever the deletion came from.
- ✅ `PinStore` publishes `layout`; `change(in:)` edits one scope. A
  `pins.plist` from before Spaces decodes into the first space.

### Windows (`TabManager`)
- ✅ Each window shows one space (`activeSpaceID`) and keeps the others
  **parked** (`ParkedSpace`: their Today and selected tab). Everything
  working on `tabs`, `favorites`, `pinned` and `activeTabID` is about the
  space shown, so closing, pinning, ⌃Tab, ⌘1–9 and the strip work unchanged.
  `show(_:)` parks the current space, reconciles the pins for the new scope
  and selects its tab (or its newest, or a new one).
- ✅ `selectTab` switches spaces first when the tab is parked, which is how
  the Command Bar's Switch to Tab reaches other spaces' tabs
  (`tabsInOtherSpaces`).
- ✅ **Rehoming**: a tab browses with its space's profile. When a space
  changes profile (in the editor, or because its profile was deleted), its
  tabs, parked ones included, and its pinned tabs are rebuilt asleep on the
  new context from their saved state; the selected one wakes. The same rule
  rebuilds a favorite whose profile changed.
- ✅ The sweep sleeps and archives parked spaces' tabs too (never "active":
  they aren't on screen). Deleting a space archives its Today in every
  window; a window showing it moves to the space before it (that window) or
  the first space (others).
- ✅ **Session**: `SavedWindow` holds a `SavedSpace` per space (tabs, the
  selected Today index or pinned tab's pin ID, which 5d's log asked for) and
  the space shown. A window saved before Spaces decodes into the first space.

### Switching and paging (`Spaces/SpacePaging.swift`)
- ✅ `spacePage`: the sidebar's sections are keyed by the active space and
  slide in from the side the new space lies on, out the other. A view
  leaving keeps the transition it was last drawn with, so `page(to:)`
  publishes `spacePagingDirection` a turn before the switch when the
  direction changes. Reduce Motion crossfades.
- ✅ `spacePaging`: `HorizontalSwipeReader`, an `NSView` that watches the
  window's scroll events (local monitor) and claims gestures over the
  sidebar whose first movement is horizontal; vertical scrolls pass through,
  and a claimed swipe swallows its momentum. The page follows the fingers,
  resists (20%) where there's no space to go, and switches past 60pt;
  otherwise it springs back. `ChromeMotion.page` (spring 0.36, bounce 0.12).
- ✅ The frame's theme is the active space's (`BrowserView`), so the tint
  animates with the switch.

### UI
- ✅ **Footer**: Library, an icon per space (the active one lit), New Space
  (+). A space's context menu: Edit Space…, Move Left, Move Right, Delete
  Space… (confirmed). A **space title** row heads the sections once there are
  two spaces, so a swipe shows which space arrived; double-click edits.
- ✅ **`SpaceEditor`** (a sheet from the window or Settings): name (focused,
  kept on Return or Done), 16 symbols, an emoji field, the theme swatches
  (moved from Settings) and a custom color, and the profile. Icon, color and
  profile apply as picked, so the frame shows the color live.
- ✅ **Top-tab mode**: once there are two spaces a `SpaceMenuButton` leads the
  strip, showing the active space's icon; it opens a menu of the spaces
  (checked), New Space and Edit Space. Like Safari's tab-group picker: the
  strip has no room for a row of dots, and with one space it stays as it
  was.
- ✅ **Spaces menu**: Next/Previous Space (⌘⌥→/←), each space with ⌃1–9, New
  Space, Edit Space…. `BrowserWebView` now lets the menu bar take every ⌃
  key equivalent first (it did only ⌃Tab), since WebKit swallowed ⌃1–9
  while a page had focus; ⌃ keys no menu claims still reach the page.
- ✅ **Command Bar**: New Space, Edit Space, and "Switch to <Space>" rows
  (`CommandBarResult.Kind.space`, shown with the space's icon) matched by the
  space's name or "space".
- ✅ **Settings › Spaces**: spaces (drag to reorder, Edit…, delete with
  confirmation, New Space) and profiles (rename in place on Return, delete
  with a confirmation that says what goes, New Profile).

## Key Learnings
- **A removed view keeps its last transition.** Direction-dependent paging
  needs the direction drawn before the switch, hence the one-turn deferral
  when it changes.
- **`@Published` sinks run in `willSet`.** Window reconciles take the new
  value as a parameter and cache it (`knownSpaces`); nothing reads the
  store's property mid-change. Context lookups go by the space's profile ID
  for the same reason.
- **WebKit swallows ⌃digit** in a focused web view before the menu bar sees
  it, as it did ⌃Tab.
- **NSEvent monitors and Swift 6**: the handler isn't main-actor typed and
  `NSEvent` isn't `Sendable`; `nonisolated(unsafe)` on the event and a `Bool`
  out of `MainActor.assumeIsolated` keep it honest.
- **Shared files between agents**: another agent's build on main read the
  new-format `pins.plist`, failed to decode, and saved empty pins over it.
  The original was restored from a backup after each run. Older builds can't
  read the new `pins.plist`/`session.plist`; this build reads theirs.
- The harness's `mouse` picked the first window over 200pt tall, which with
  a sheet open is the sheet; it now takes the largest window.

## Decisions for the coordinator
- **Favorites are per profile**, shared by that profile's spaces (Arc's
  behavior), not global: a global favorite would open its site signed in as
  whichever profile the space uses. With one profile it's the same as shared.
- **Today is per window and space**, like Today was per window before.
  Spaces and pins are shared by all windows.
- **History, downloads, Boosts and content-blocking exceptions stay global**
  across profiles; only site data (cookies, storage, cache) and site
  permissions are per profile.
- **Deleting a profile moves its spaces and Favorites to the default
  profile** and deletes its site data. Deleting a space archives its Today.
- The **Appearance theme swatches moved into the space editor**; the old
  setting seeds the first space.
- New windows (⌘N) open on the first space.
