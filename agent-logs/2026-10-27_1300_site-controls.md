# Site Controls and Private Windows

**Date:** 2026-10-27
**Agent:** Claude Opus 5.5
**Branch:** `site-controls`, PR to `main`
**Status:** ✅ Complete; section 5i of ARC-PARITY.md ticked

## User Intention
Section 5i of `ARC-PARITY.md`. First, Arc's per-site controls from the URL
pill's leading glyph: connection security with a certificate summary,
camera, microphone and location permissions, content blocking on or off for
the site, the site's zoom, and Clear Site Data. Second, private windows
(⇧⌘N) on a non-persistent data store that leave no history or session,
look distinct, and are built so 5e's profiles (a data store per profile)
can extend them. Ran in parallel with 5c (tab sleeping) and 5h (media), and
rebased onto both.

## What We Accomplished

### Site controls
- ✅ **`SiteControlsButton`**: the lock or globe glyph at the front of the
  sidebar's URL pill and of the top-mode address field. On a website it's
  an accessory button that opens the popover. On a start page it stays a
  plain search glyph. Clicking the domain still opens the Command Bar.
- ✅ **One anchor at a time.** Docked sidebar, floating sidebar and top
  toolbar each hold a button, so `TabManager.isShowingSiteControls` is
  presented only by the one on screen (`presentsSiteControls`). With a
  hidden sidebar the shell reveals it and keeps it out until the popover
  closes. The floating sidebar presents only once it's out: asked to open
  from offscreen, the popover failed and reset the flag.
- ✅ **`SiteControlsPanel`**: favicon and domain; "Connection is secure",
  "Parts of this page are not secure" or "Connection is not secure", plus
  "Issued to *.wikipedia.org by YE2, valid until 3 Jan 2027"; Block Ads
  and Trackers (a switch, disabled with a tooltip when blocking is off in
  Settings); Zoom −/100%/+ (the percentage resets); Camera, Microphone,
  Location as Ask/Allow/Block menus; Clear Site Data. It's a native
  popover. Rows use the chrome metrics, `ChromeButtonStyle` and a fixed
  icon column.
- ✅ **`ConnectionSecurity`** reads `serverTrust` and
  `hasOnlySecureContent`. WebKit only shows a page whose certificate it
  trusted, so HTTPS plus a certificate is secure. Subject and issuer come
  from `SecCertificateCopySubjectSummary` over the chain, expiry from
  `SecCertificateCopyNotValidAfterDate`.
- ✅ **Permissions**: `SitePermissions` is now an `ObservableObject` with
  `answer(for:at:)` and `setAnswer(_:for:at:)` (nil forgets, so the site
  asks again). Keys are an `Origin` (scheme, host, port, default port
  dropped), so a page URL and a `WKSecurityOrigin` agree.
- ✅ **Clear Site Data** fetches the store's records, removes every type
  for those whose registrable domain covers the host, reloads, and toasts
  "Cleared Data for 127.0.0.1". WebKit keeps records by registrable domain,
  so a subdomain clears its whole site.
- ✅ **Site Settings** in the Command Bar (offered on websites only).
- ✅ **`Site`**: a host without "www." that covers its subdomains. Shared
  by the pill's domain, the blocking exceptions and Clear Site Data.

### Content blocking per site
- ✅ `ContentBlockerManager` keeps a set of excepted domains
  (`browser.contentBlockingExceptions`). `blocks(on:)` and
  `setBlocks(_:on:)` drive it. Turning blocking back on also lifts a parent
  site's exception.
- ✅ **Why not `ignore-previous-rules`**: an `if-domain` exception only
  reaches rules in its own list, so it would mean recompiling EasyList
  (27k rules) for every change. Every web view already has its own
  `WKUserContentController`, so a page on an excepted site just goes
  without the list. `update(_:for:)` runs as each main-frame navigation is
  decided, adding or removing the list before the page loads. Toggling
  reloads the page.

### Private windows
- ✅ **`BrowsingContext`**: what a window browses with. It holds the
  `WKWebsiteDataStore`, the site permissions, and `isPrivate`. Normal
  windows share `AppServices.browsingContext`; each private window makes
  its own (`.nonPersistent()`). It goes through `TabSessionServices.context`
  into `wake()`, the one place web views are made
  (`makeWebView(in:)`). A profile becomes another context.
- ✅ **Nothing written down**: `TabManager` takes `session: SessionStore?`
  and `archive: TabArchive?`, both nil for a private window, so it's never
  saved, restored or archived (`archiveAfter` is nil; tabs still sleep, in
  memory). History visits are skipped, site zoom isn't remembered, and it
  has its own `RecentlyClosedTabs`. The Command Bar shows no archive there.
- ✅ **Its own scene**: `WindowGroup("Private Window", id: "private")`,
  `.handlesExternalEvents(matching: [])`, and the window never registers
  with `ExternalURLRouter`, so links from other apps and History go to
  normal windows. Both groups share `browserWindowStyle()`.
- ✅ **Looks private**: `ChromeTheme.privateBrowsing` (#2E2560) darkens the
  frame to indigo in dark mode and lavender-gray in light, plus a
  `PrivateBadge` ("Private" in the toolbar, icon only in the sidebar
  header, where the word didn't fit).
- ✅ File › New Private Window ⇧⌘N, and New Private Window in the Command
  Bar. The media player works there (it's per `TabManager`).

### Tests
- ✅ `SiteTests` (www, subdomains, hostless pages, origin port
  normalization, forgetting an answer) and `ContentBlockingExceptionTests`
  (exceptions cover subdomains and survive a relaunch, re-enabling lifts a
  parent's exception).

## Key Learnings
- A rule list's `ignore-previous-rules` stops at its own list. Per-web-view
  controllers make per-site blocking a matter of attaching or not.
- A SwiftUI popover asked to open from an offscreen view fails and writes
  false back to its binding.
- Region captures pick up other agents' Cove windows on top of yours; use
  `-l<windowid>` per window, and re-check focus right before every click.
  Re-activating the app closes a transient popover, so the open and the
  click inside it go in one burst.

## Deferred
- Private windows still cache favicons in `favicons.db` and list their
  downloads in the shared download manager. Both would want a per-context
  store.
- History › Recently Closed shows the shared list in a private window.
  Reopening from it there does nothing.
- Content-blocking exceptions are shared by private and normal windows
  (a setting, not a trace, but it does name the site).
- Permission changes apply the next time the site asks. A camera already
  in use isn't stopped when it's switched to Block.
- The Command Bar ranks "Site Settings" below the search row for the
  exact query "site settings". That's the ranker's general command
  weighting.
