## User Intention
Workstream 4 of `ARC-PARITY.md`: bring the chrome's look and motion to Arc
parity on top of the layout (PR #4) and the Command Bar (PR #5), keeping
Cove's native character and its top-tab mode. Theme color, page card
elevation, a thin progress indicator, link hover preview, Copy URL with a
toast, motion with Reduce Motion, start page polish, the raised active
sidebar tab, a Settings restyle, and the layout PR's leftovers (rows under
the sidebar header, a hover fill on the pill). No feature work.

## What We Accomplished

### Tokens (`ChromeTokens.swift`)
- ✅ **`ChromeShadow`**: four elevation levels, `raised` (active sidebar
  tab), `card` (the page), `floating` (revealed chrome, toasts, the link
  preview) and `panel` (the Command Bar), drawn by `chromeShadow()`, which
  doubles the opacity in dark mode. The three ad-hoc shadows are gone.
- ✅ **`ChromeMotion`** gains `slide` (spring, bounce 0.18, for chrome
  arriving from an edge), `tab` (the one open/close duration for both tab
  presentations), `appear` (toasts), `fade`, `progress`.
- ✅ `ChromePalette.shell` and the new `ChromePalette.raised` are
  `ShapeStyle`s that resolve in the environment, so every existing
  `.fill(ChromePalette.shell)` picked up the theme with no call-site change.

### Theme (`ChromeTheme.swift`)
- ✅ **`ChromeTheme`** is a value: an optional tint `Color`, stored as hex
  under `browser.themeColor`, injected with `.environment(\.chromeTheme)` in
  `BrowserView`. A Space can later carry its own by setting the same key.
- ✅ `frameColor(in:)` mixes the system under-page gray with the tint in
  Oklab: 0.24 in light, 0.22 in dark, halved under increased contrast. Text
  and controls keep their system colors, so legibility is untouched. The
  page card stays `textBackgroundColor`; nothing is glass.
- ✅ **Raised style**: the page's color in light mode (Arc's white card on a
  tinted frame); in dark mode the page is *darker* than the frame and read
  as sunken, so the lift is the frame mixed with 9% white, which keeps the
  tint. Used by the active sidebar tab, the favorite tile and the Command
  Bar's surface.
- ✅ **Settings › Appearance**: seven swatches (system gray plus six Arc-like
  colors) with an accent ring on the chosen one, a `ColorPicker` for custom,
  and the tab layout toggles, which were under Browsing by accident.

### Page
- ✅ **Card shadow** (`ChromeShadow.card`), drawn on a background shape
  behind the clip so the clip can't cut it off.
- ✅ **Progress**: `PageProgressBar`, a 2pt accent line along the page's top
  edge. Chose the line over Arc's active-tab shimmer because it shows in
  all four tab modes, including both hidden ones where there is no tab to
  shimmer. It only grows: a new load snaps back instead of visibly
  shrinking, and a finished load fills before fading (`fade.delay(0.15)`).
- ✅ **Link preview**: `LinkHover` installs a `WKUserScript` (document start,
  all frames, `.defaultClient` world) watching `mouseover` for `a[href]` and
  `mouseleave` on the document element, and a `WKScriptMessageHandler` that
  relays to `TabSession.hoveredLink`. `LinkPreview` shows it bottom-leading
  on `.regularMaterial`, delayed 0.1s so sweeping a list doesn't flicker.
  Navigation and a replaced web view clear it.
- ✅ **Copy URL** (`TabManager.copyURL()`): Browser › Copy URL ⌘⇧C and the
  Command Bar's command both go through it. `ToastCenter` holds one toast
  per window for 1.6s; `ToastOverlay` draws it as a capsule springing in at
  the top of the page. Both overlays sit inside the page card's `ZStack`,
  so they're clipped by its corners and never over the sidebar.

### Motion
- ✅ `chromeSlide(isShown:from:)`: the floating sidebar and tab row slide in
  with `ChromeMotion.slide`; under Reduce Motion they crossfade instead
  (`offset` is only applied when motion is allowed).
- ✅ `ChromeTabSlot` replaces the strip-private `TabSlot`, takes an axis, and
  has an asymmetric removal that scales the tab to 0.8 as its slot
  collapses and fades: the poof. The sidebar's rows use it too, so tabs open
  and close the same way in both presentations. Insertion is unchanged.
- ✅ The Command Bar already scaled and faded in (`ChromeMotion.commandBar`);
  its surface changed, not its motion.

### Sidebar and fields
- ✅ The header carries the frame color behind it, fading over the 8pt gap
  below the pill, so rows scroll *behind* the header instead of showing
  through around the pill. The 8pt comes from the geometry: anything taller
  would dim the first row at rest.
- ✅ `chromeFieldStyle` deepens its fill on hover unless focused, which gives
  the URL pill, the address field and the start page field Arc's hover.

### Start page
- ✅ The thin "Cove" wordmark is gone; the field moves up into its place.
- ✅ `SiteMonogram`: tiles without a favicon show the host's initial on a

  all land on one hue), so a site keeps its color across launches.

### Command Bar polish

### Settings

## Key Learnings
- **The Mac was locked for most of the session.** With the lock screen up,
  nothing can activate: `NSRunningApplication.activate`, System Events
  `set frontmost`, AX `kAXFrontmost`, HID clicks all fail silently, and
  AppKit's state restoration left SwiftUI apps with *no window* until
  launched with `-ApplePersistenceIgnoreState YES`. `screencapture -l`
  still renders windows and `CGEvent.postToPid` still delivers keys, but
  SwiftUI `Commands` resolve `@FocusedObject` from the key window, so ⌘T,
  ⌘W, ⌘⇧C are disabled while no window is key; ⌘, works because Settings is
  AppKit's. Check `CGSessionCopyCurrentDictionary()["CGSSessionScreenIsLocked"]`
  before blaming the app.
- **Session restore is shared across instances** and sibling agents' tests
  left tabs whose pages `confirm()` on load, which blocks the window behind
  a sheet. The harness clears `session.plist` before each launch and the
  backup from the session start is restored at the end. A seeded
  `session.plist` is also the easiest way to get a window of a given size
  and a sidebar with 30 tabs without any input.
- **`screencapture` bursts can't see a 0.18s animation** (each capture
  takes about as long). `screencapture -V <seconds> -R <rect>` records a
  movie; `ffmpeg -vf fps=60` turns it into frames, a per-frame diff finds
  the motion, and `tile=6x2` gives a contact sheet. Keep the rect on your
  own window: a user's window drifting into it ends up in the frames.
- `git add -p` is the wrong tool for splitting a file whose hunks are
  adjacent; writing the intermediate file variants and amending in a
  scripted `rebase -i` keeps every commit buildable.
- `ShapeStyle.resolve(in:)` is the clean way to theme: one environment value,
  zero call-site changes, and `Color.mix(in: .perceptual)` gives pastels
  that don't go muddy.
