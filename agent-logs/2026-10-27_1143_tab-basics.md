## User Intention
Section 5a of `ARC-PARITY.md`: the everyday tab handling Arc has and Cove
lacked. Keyboard switching, drag to reorder, a tab context menu, renaming
that survives relaunch, an audio indicator with mute, ⌘S for the sidebar,
and Command Bar commands where they fit. Pinning (5d), tab sleeping and
archiving (5c) and page tools (5b) are other agents' work in parallel, so

## What We Accomplished

### Order (`TabOrder.swift`, tested)
- ✅ Everything that moves through tabs follows the order they're **shown**
  in: `TabManager.tabsInDisplayOrder` is the strip's oldest-first order,
  or the sidebar's newest-first Today. Pinned and Favorites join it when
  5d fills them.
- ✅ Four small `Array where Element: Identifiable` helpers: the neighbor
  `offset` away (wrapping), the ⌘-digit target (1–8 by place, 9 the last),
  the elements after one, and `move(_:onto:)`. The move puts the element
  at the target's index, which lands it where it was dropped whether the
  list is shown forward or reversed, so the sidebar needs no special case.
  Six Swift Testing tests.

### Switching
- ✅ **Tab › Show Next Tab ⌃⇥, Show Previous Tab ⌃⇧⇥, Go to Tab ›
  Tab 1–8 ⌘1–8, Last Tab ⌘9**, in a new `TabCommands` (its own file and
  `Commands`, so it doesn't collide with 5b's menu work).
- ✅ **WKWebView swallows ⌃Tab** while the page has focus (it worked from
  the start page, never from a page). `BrowserWebView`, a five-line
  subclass made by `WebKitEnvironment`, offers ⌃Tab to the main menu first
  in `performKeyEquivalent`. Pages can't use ⌃Tab in Safari either.

### Sidebar toggle
- ✅ **⌘S** is View › Hide Tabs (hides the sidebar, or the top tabs in
  top mode). `browserLayoutCommands` takes the shortcut as a parameter so
  only the View copy claims it, not the Browser menu's copy too.
- ✅ ⌘⇧C Copy URL was already there (look-and-feel PR); it now goes through
  `copyURL(of:)`, which a tab's Copy Link shares.

### Context menu and Tab menu (`TabActions`)
- ✅ One view, two placements: a tab's context menu (Duplicate Tab, Rename
  Tab…, Copy Link, Mute/Unmute Tab, Close Tab, Close Other Tabs, Close Tabs
  Below) and the Tab menu for the active tab, which leaves out what the
  menu bar already has (Copy URL, Close Tab) and Rename, which edits in
  place. In top mode the last item reads **Close Tabs to the Right**.
  Pinning slots in at the top.
- ✅ `ChromeTabItem` takes the `TabManager` instead of select/close
  closures, so the menu and renaming live with the tab in both
  presentations.
- ✅ `TabManager`: `duplicateTab` (a copy beside the original, restored from
  its `savedTab`, so back/forward history comes along), `closeOtherTabs
  (keeping:)`, `closeTabs(below:)` (selects the clicked tab if the active
  one is among those closed).

### Rename
- ✅ Double-click a tab, or Rename Tab…: the title becomes a plain field
  with the name selected. Return or clicking away keeps it, Escape cancels,
  an empty name gives back the page's title. The double-click is a
  `simultaneousGesture`, so single clicks select without waiting for a
  possible second click, and it doesn't zoom the window from the strip.
- ✅ `TabSession.customTitle` and `title` (custom, else the page's). The
  strip, the sidebar, the favorite tile's help and the Command Bar's
  Switch to Tab rows use `title`; history keeps the page's own.
- ✅ Persists: `SavedTab.customTitle` is optional, so sessions saved before
  it decode unchanged. `TabSession.savedTabChanges` publishes whenever the
  saved form changes; `SessionStore` merges those instead of reaching into
  `$currentURL`, which also gives 5c one place to add its own fields.

### Audio (`PageAudio.swift`)
- ✅ **The public API can't do it.** `requestMediaPlaybackState` is a
  one-shot query, counts silent and muted video as playing, and there's no
  KVO; `setAllMediaPlaybackSuspended` and `pauseAllMediaPlayback` pause
  rather than mute; there's no public mute (`_setPageMuted:` and
  `_isPlayingAudio` are SPI). So: a `WKUserScript` at document start in
  every frame, in the `.defaultClient` content world (the page can't see
  or tamper with it), listening in the capture phase for `play`, `playing`,
  `pause`, `ended`, `emptied` and `volumechange` on `<audio>`/`<video>`.
- ✅ A frame reports when it starts or stops making sound (playing, not
  ended, volume above zero, not muted by the page). It's a
  `WKScriptMessageHandlerWithReply`: the reply carries the tab's mute
  state, so a frame that starts playing in a muted tab mutes itself at
  once, and a page that unmutes its own media is muted again.
- ✅ Muting sets `muted` on the elements and remembers which ones it
  silenced (a `WeakSet`), so unmuting restores only those. The tab pushes
  a change to the frames playing now with `callAsyncJavaScript(in:
  frame)`, using the `WKFrameInfo` each frame reported from, so
  cross-origin iframes are reached too. Frames are forgotten on
  `pagehide` and on main-frame commit.
- ✅ The tab shows a speaker while it plays and a crossed-out speaker while
  muted (even when quiet, so it can be unmuted). Clicking it toggles
  without selecting the tab. The two accessories sit together so narrow
  top tabs keep room for the title.
- Limit: Web Audio, and media elements never inserted into the document,
  aren't seen. Covering them means patching the page's own prototypes in
  the page world; not worth it for an indicator.

### Drag to reorder (`TabReordering.swift`)
- ✅ `reorderableTab(_:in:dragging:)`: `onDrag` plus a `DropDelegate` per
  tab. Entering a tab moves the dragged one into its place, so the list
  makes room as you drag and the existing tab-order animation runs; the
  drop just ends it. `acceptsTabDrops` on the list catches drops in the
  gaps so the preview doesn't fly back.
- ✅ The drag carries a private, process-only `com.cove.browser.tab` type
  (declared in Info.plist), so links and files dragged from elsewhere
  never reorder tabs, and a tab dropped on the page carries no URL to
  navigate to.
  Sections can accept the same type with their own delegates (5d).
- ✅ **The titlebar moves the window on any drag**, before SwiftUI sees it:
  `onDrag`, and even a plain `DragGesture`, lost to it. Not
  `windowBackgroundDragBehavior` (tried disabling it). `WindowDragExclusion`
  in `TabStripView` sets `window.isMovable = false` while the pointer is
  over a top tab (a tracking area), and restores it when the pointer
  leaves or the tab goes away under it. The strip's empty space still
  drags the window.

### Command Bar
- ✅ Duplicate Tab, Mute Tab / Unmute Tab (only when there's sound to mute,
  or the tab is muted), Close Other Tabs (with more than one tab).

## Key Learnings
- **WKWebView keeps some key equivalents.** Menu items with ⌃Tab never fire
  while a page is first responder (probably because WebKit re-sends keys
  the page didn't handle as `keyDown`, past the menu). Offering the
  event to `NSApp.mainMenu` first in a `performKeyEquivalent` override
  fixes it without touching other keys.
- **Content in the titlebar can't start drags.** With a toolbar and a full
  size content view, AppKit starts a window move on mouse-down-and-drag in
  the titlebar band regardless of SwiftUI gestures. Toggling
  `NSWindow.isMovable` from a tracking area is the smallest fix that
  keeps the empty strip draggable.
- **Content worlds share the DOM, not the JS.** A client-world script can
  set `media.muted` and hear media events, while its globals (the
  `pageAudio.setMuted` hook) stay invisible to the page.
- `WKScriptMessageHandlerWithReply` imports into Swift as an `async`
  method returning `(Any?, String?)`; the completion-handler form doesn't
  satisfy the protocol.
- **Synthetic input under contention:** `NSRunningApplication.activate`
  from a command-line tool no longer brings another app forward; System
  Events `set frontmost` does. Another agent's Cove kept taking focus and
  overwriting the shared `session.plist`, so persistence was checked by
  quitting with ⌘Q and reading the plist straight away.
