## User Intention
Section 5l of `ARC-PARITY.md`: Arc's Capture (⌘⇧2, the Command Bar, the
page's context menu; a region or an element; copy, save, send to a note or
an easel), Notes (rich text that lives in the sidebar like tabs, in Today,
Pinned and folders, per space, searchable, never archived while pinned) and
Easels (a freeform canvas of text, images, drawings and live web clippings,
with pan, zoom, select, move, resize, delete and undo). The sidebar model
was to grow an explicit item kind rather than fake notes as tabs.

## What We Accomplished

### Capture
- ✅ **`ElementPicker`**: Zap's hover outline and click-swallowing picker,
  pulled out of `BoostZap` and generalized over a content world, a tint and
  a JavaScript `report` function. Zap reports a selector through it;
  Capture reports a bounding rect.
- ✅ **`CaptureSession`** (`PageCapture.swift`): region mode (a dimmed
  overlay with a crosshair, the selection cut out of the dim with its size)
  or element mode (the picker in Capture's own content world). Both end in
  `WKWebView.takeSnapshot` with a rect. **`PageGeometry`** (pure, tested)
  converts between the view's points and the page's CSS pixels using the
  scroll offset and `innerWidth`, so zoom is accounted for.
- ✅ A **`Capture`** keeps the image and a **`CaptureSource`**: URL, title,
  the region in document CSS pixels and the viewport width: what a live
  clipping needs. PNGs are written with their point size, so they open at
  screen size.
- ✅ The result bar: thumbnail, Copy (PNG + TIFF), Save… (PNG save sheet,
  "Capture of <title>"), Send to Note and Send to Easel (each a new one or
  one of the recent eight), Done (Escape).
- ✅ Entry points: File › Capture… ⌘⇧2, Command Bar "Capture", and
  "Capture…" at the end of the page's context menu
  (`BrowserWebView.willOpenMenu`, wired through `TabSession.Host.capture`,
  which selects the tab first so split panes work). Shown over the page or
  split pane it started on, like the Boost editor; selecting another tab
  ends it.

### Notes
- ✅ **The model**: `SidebarItem` gains `.document(UUID)` (the same in the
  saved and live trees, so `map`, moves and folders need nothing new) and
  `leaves`/`documents`. Today becomes `today: [TodayItem<TabSession>]`
  (`.tab` or `.document`); `tabs` is now derived, and `TabEntry` gains
  `.document`. All of TabManager's Today edits (open, close, archive, pin,
  release, drag, splits, rehoming, parked spaces) were moved onto `today`.
- ✅ **Selection**: `activeDocumentID`, a note shown in the card in place
  of the active tab's page. The active tab stays selected underneath, so
  `BrowserView`, the shell and every `activeTab` user keep working;
  selecting any tab clears it. `isSelected(_:)` decides which row is lit.
  While a note is shown: page tools and Capture are off (`activePage` is
  nil), navigation buttons are disabled and Back/Forward/Reload do nothing,
  ⌘L opens the Command Bar for a new tab, ⌘W closes the note, the URL pill
  and the top bar show the note's glyph and title, and the Tab menu shows
  the note's actions. History's Recently Visited and the Command Bar bring
  the page back before navigating it.
- ✅ **`DocumentStore`** (one per app): an index (`Documents/index.plist`:
  id, kind, title, text for search, dates) and one file per document
  beside it. Live documents are loaded once and shared by every window.
- ✅ **`Note`**: the note's one `NSTextStorage`. Each editor lays it out
  with its own TextKit 1 layout manager, so a note open in two windows
  changes in both as it's typed. Saved as RTFD a second after the last
  edit, with colors stripped (drawn in the system's text color, so light
  and dark both read) and lists flattened (RTF rewrites AppKit's lists on
  read and loses custom markers; they're rebuilt from the markers).
- ✅ **Editor** (`NoteView`, `NoteTextView`): title field, then the text in
  a readable column. Text styles (Title, Heading, Subheading, Body), bold,
  italic, underline, strikethrough (⌘B/⌘I/⌘U), bulleted and numbered
  lists and checklists (Return continues, Return on an empty item ends,
  clicking a box checks it and strikes the item), links (⌘K sheet; clicks
  open new tabs), pasted and dropped images, captures appended with a link
  to their page. Every change goes through `shouldChangeText` so it's
  undoable.
- ✅ **Sidebar and strip**: `DocumentTabItem` (shares the tab's surface
  through the new `chromeTabSurface` modifier taken out of
  `ChromeTabItem`): glyph, title, rename in place, a close button in
  Today, drag like a tab between Today, Pinned and folders. Context menu:
  Pin/Unpin, Rename, Close, Delete… (confirmed). Pinned notes lead the top
  strip icon-only, like pinned tabs.
- ✅ **Lifetime**: made with File › New Note ⌃⌘N, the New Tab row's menu or
  the Command Bar; closing removes a note from Today but keeps it; Today
  lets go of idle notes on the tab archive timer (reusing `TabIdlePolicy`);
  pinned notes stay. The Command Bar finds every note by title or words
  ("Notes" section) and brings it back into Today. Deleting removes the
  file, the index entry, and every placement in every window and space.
- ✅ **Session**: `SavedSpace.documents` (each note's place among Today's
  tabs) and `activeDocumentID`, both optional, so older sessions decode.
  Spaces park their note on screen too.

### Easels
- ✅ **`EaselBoard`** (pure, tested): items with frames: text, image (a file
  in the package), drawing (strokes normalized 0–1 to the frame so they
  stretch), and clip (a `CaptureSource` plus snapshot file). Moves, bring to
  front, removal, placement below everything, searchable text.
- ✅ **`Easel`**: the live board with its own `UndoManager` (whole-board
  snapshots per step, which are small); saved a second after the last
  change as a package `<id>.easel/` with `board.plist` and PNGs. Images no
  item uses are removed the next time the easel opens, so undo can still
  bring back what was deleted this session.
- ✅ **Canvas** (`EaselCanvasView`, AppKit in a magnifying scroll view):
  pan by scrolling, pinch or the bar's buttons to zoom (25–300%). Select
  (Shift adds), move, resize from the corner handle (images and clippings
  keep their shape unless Shift), Delete, ⌘Z/⇧⌘Z, select all; Text tool
  places a box (double-click to edit, Escape or clicking away commits, an
  empty box goes away); Draw tool with six inks; Add Image… and paste or
  drop images; paste text as a box. Item menu: Bring to Front, Delete; for
  clippings Refresh Clipping, Open Page, Stop Live Updates (keeps the
  snapshot as an image).
- ✅ **Live clippings** (`EaselClipView`): a small `WKWebView` loads the
  page at the captured viewport width, `pageZoom` scales the region to the
  item, the view is shifted left by the region's x and scrolled to its y
  (again 0.8s later for late layout); the snapshot shows until then. It
  doesn't take clicks. **Fidelity limits** (documented on the type): pages
  that lay out differently at another height, that move content after load
  (feeds, ads, lazy images), that scroll an inner element instead of the
  document, or that show something else when signed out won't match the
  region. Clippings load only while their easel is on screen.

### Private windows
No notes or easels at all: a private window gets no `DocumentStore`, so it
shows none, can't make any, and Capture offers only Copy and Save. Same
reasoning as pins and Boosts: a note writes to disk, and showing the
user's notes in a private window would mix the two.

## Key Learnings
- **Lists in RTF**: Cocoa's RTF reader rebuilds `NSTextList` markers its
  own way and dropped every marker on read-back here. Saving markers as
  plain text without `textLists` and restoring lists from the markers on
  load round-trips cleanly (tested).
- **`groupsByEvent`**: two undoable changes in one run-loop turn undo
  together; in the app each click is its own turn, in tests group by hand.
- **The Edit menu's Undo goes to the window**, not the responder's
  `undoManager`; a view with its own history implements `undo:`/`redo:`.
- **The shared `session.plist` was overwritten** by another agent's build
  between my launches, so Today lost my notes twice; the notes themselves
  were safe in the store and came back through the Command Bar.

## Decisions for the coordinator
- **A note on screen sits over the active tab** rather than replacing it:
  the tab-centric shell stays intact; the alternative (an optional active
  tab everywhere) touched far more code.
- **Closing a note keeps it** (it leaves Today, like an archived tab, and
  the Command Bar finds it); only Delete… removes it.
- **Notes can be pinned, not made Favorites** (Favorites are site tiles).
  Splits stay tabs only.
- **Live clippings don't get extensions** (no extension controller, no
  content blocker): a clipping is a view of a page, not a tab. They use
  the space's profile data store so signed-in pages stay signed in.
- Shortcuts: ⌃⌘N New Note, ⌃⌘E New Easel, ⌘⇧2 Capture.
