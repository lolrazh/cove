## User Intention
Section 5h of `ARC-PARITY.md`: Arc's media player. When a tab in the
background plays audio or video, the sidebar shows its favicon, title and
site with play/pause, skip back and forward (track changes when the page
supports them), mute, and a click through to the tab. Build on 5a's
`PageAudio` rather than add a second monitor; keep `TabSession` edits small
because 5c (tab sleeping) was rewriting it in parallel. 5c merged first, so
this branch is rebased onto it.

## What We Accomplished

### `PageMedia` (was `PageAudio`)
- ✅ Renamed in its own commit, then generalized. The client-world script
  still reports audibility and mutes as before, and now also tracks the
  **current media**: the last element to play *with sound* (so silent
  autoplay loops never get a player), kept while paused, dropped once it
  leaves the document. Each report carries `{ playing, title, artist,
  previous, next }` or `null`, and is sent only when its JSON changes.
- ✅ Title and artist come from `navigator.mediaSession.metadata`, which the
  client world can read directly (same native object). Without metadata the
  player falls back to the tab's title, and to the site for the subtitle.
- ✅ **Media Session handlers can't be read from another world**, and
  there's no API to invoke them. So a tiny second user script in the
  **page** world wraps `MediaSession.prototype.setActionHandler` (and the
  `metadata` setter) to remember handlers and announce changes. The two
  worlds talk with cancelable `CustomEvent`s on `document`: the client
  world dispatches `pageMedia-query`/`pageMedia-action` with the action
  name as `detail`, the page world calls `preventDefault()` if it has (and,
  for actions, runs) the handler, and `dispatchEvent`'s return value says
  so, synchronously. No shared globals, no attributes in the DOM.
- ✅ `perform(_:)` asks the page first for every action (Spotify-style pages
  want their own play/pause handlers), then falls back to the element:
  `play()`, `pause()`, `currentTime ±10`. `previoustrack`/`nexttrack` exist
  only through the page.
- ✅ Frames: the player follows the frame that last started playing; if its
  media goes away it falls back to another frame with media.
  `closePlayer()` pauses and hides until something plays again.
- ✅ A media element taken out of the document pauses where the document's
  capture listeners can't hear it, so the script also listens for `pause` on
  the current element itself (the same listener function, so re-adding is a
  no-op).

### `TabSession` (kept small, on top of 5c)
- `@Published nowPlaying`, `media` readable (nil while asleep). The monitor
  reports a `Status { isAudible, nowPlaying }`; `sleep()` and
  `discardPage()` clear `nowPlaying`, so **a paused tab that falls asleep
  just leaves the player** (5c never sleeps an audible tab).

### `TabManager.mediaTab`
- The background tab the player controls: among tabs other than the active
  one, the first playing one in display order, else the first with paused
  media (`Sequence.preferringPlaying`, tested). Kept current by merging
  every tab's `$nowPlaying` with `$activeTabID`; since `@Published` sends
  before the value lands, the pick hops one main-queue turn.

### `MediaPlayer` (UI)
- **Sidebar:** a raised card above the footer (shown in the docked sidebar
  and in the floating one when hidden tabs are revealed): favicon, title,
  artist or site, close on hover; below, skip back, play/pause, skip
  forward, and mute on the trailing edge. Clicking the top row shows the
  tab. Skip icons are `backward.fill`/`forward.fill` for tracks and
  `gobackward.10`/`goforward.10` for seeking.
- **Top tabs:** a compact control in the navigation bar between the address
  field and downloads: the tab's favicon (click to show it, help gives the
  title) and play/pause. The strip already shows the speaker on the tab, so
  this stays small. `NavigationBar` now takes the `TabManager` instead of an
  `onEditAddress` closure.
- Symbols in `ChromeSymbols.Media`; each `MediaAction` knows its symbol and
  help text.

### Command Bar
- **Pause Media / Play Media**, offered only when the player has something
  playing or paused.

### System Now Playing
- Not integrated on purpose. WebKit runs its own Now Playing / remote
  command session for media in a `WKWebView` (that's how media keys reach
  a page's Media Session handlers), and a second `MPNowPlayingInfoCenter`
  session from the app would compete with it. I couldn't confirm that from
  a script: on macOS 15.4+ MediaRemote queries need an entitlement and come
  back empty (`pid 0`), and the logs are private. Worth an eyeball check in
  Control Center while something plays.

## Key Learnings
- **Cancelable events are a synchronous bridge between content worlds.**
  `dispatchEvent` runs listeners in every world before it returns, and
  string `detail`s cross fine, so one world can ask the other "do you
  handle X?" and get the answer from the return value.
- A client-world script can read `navigator.mediaSession.metadata` set by
  the page, but not its action handlers, and has no way to invoke them.
- Detached media elements' events don't reach `document` listeners, even in
  the capture phase; listen on the element.

## Deferred
- Video frame thumbnail / artwork. `MediaMetadata.artwork` URLs are
  available and would be cheap to show; a live frame would need
  `takeSnapshot` of a background web view. Left out to keep the card small.
- Web Audio and never-attached `new Audio()` still aren't seen (5a's limit).
- Not checked on real sites (YouTube, Spotify) to avoid playing sound on
  the user's machine; the local pages cover the same paths.
- The `www.`-stripping host display now exists in five places; a shared
  `URL` helper would be a small follow-up outside this branch's scope.
