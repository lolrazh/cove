## User Intention
Workstream 3 of `ARC-PARITY.md`: Arc's ⌘T/⌘L palette. One floating panel over
the page that replaces the start page for new tabs, with ranked, grouped
results from open tabs, history, the search engine, the input itself, and
app commands. Keyboard-first, quiet, native, built so the layout agent's
sidebar URL pill lands on the same entry point as ⌘L.

## What We Accomplished

### Behavior
- ✅ **⌘T** opens the bar empty: Recent pages and the available commands.
  Return opens the result in a new tab, or in the current tab when that is
  an empty start page (so the first tab after launch gets reused).
- ✅ **⌘L** (Browser › Open Location) opens it with the current URL selected.
  Return navigates the current tab. **⌘Return** always opens a new tab.
- ✅ **↑/↓** move the selection, **Tab** (and → at the end of the text) accept
  the inline completion, **Escape** or a click outside dismisses. Focus
  returns to the page afterwards.
- ✅ **Inline completion**, Safari-style: a single word that starts a visited
  site's address fills in the rest of the host as a selected suffix; once a
  `/` is typed it completes the whole URL. Never while deleting.
- ✅ **New Tab buttons** (⌘T, the + in the tab strip, the sidebar row) all go
  through `TabManager.newTab()`, which asks Settings. "New tabs open with"
  gains **Command Bar**, now the default; Start Page, Blank Page and Home
  Page stay. The start page also remains what the first and reopened tabs
  show, since the bar has nothing to put in a tab.
- ✅ **Search suggestions** from the selected engine (Google, DuckDuckGo,
  Kagi, all speaking the OpenSearch/Firefox JSON form), debounced 150 ms,
  cancelled on every keystroke, 2 s timeout, only for input that would be
  searched. A Privacy setting turns them off.

### Ranking (`CommandBarRanker`, pure, tested)
Sections in order; empty sections are dropped:
1. **Top hits** (no header): the completion's page, then the input itself as
   an address (`NavigationRequestBuilder.destination(for:)`) or a search.
2. **Switch to Tab**: open tabs other than the active one, best match first.
3. **History**: distinct pages from `HistoryStore.pages(matching:)` (FTS5
   prefix match per word, frecency = Σ 1 / (1 + age in days) per visit),
   re-ranked by match quality, ties by frecency.
4. **Commands**: titles and keywords, every typed word must start a word.
5. **Suggestions**: from the engine, minus the query itself.

Match quality: every word must appear in the title or address; the address
starting with the input (3) beats a title word starting with the first word
(2) beats a plain substring (1). Words are normalized like displayed
addresses, so a pasted `https://www.github.com/` still finds GitHub.

The completion's top hit is whatever the completed host names, in this
order: an open tab, a visited page, the bare address. So the field and the
first row always agree. Pages already shown as a top hit or open tab are not
listed again under History.

### Architecture
```
CommandBar/
  CommandBarResult.swift   result + section model, CommandBarCommand
  CommandBarRanker.swift   pure ranking and completion
  SearchSuggestions.swift  engine suggestion client (nonisolated)
  CommandBarModel.swift    per-window state; owned by TabManager
  CommandBarField.swift    NSTextField: keys, completion suffix, focus
  CommandBarView.swift     overlay, panel, rows
CoveTests/
  CommandBarRankerTests.swift   Swift Testing, 16 tests
```
- `TabManager.commandBar` is a lazy, unowned-back-referenced model: one per
  window, no globals. `TabManager.newTab()` and `editCurrentURL()` are the
  two entry points; `focusAddressBar()` and the whole address-focus-request
  path (`TabSession.addressFocusRequest`, `AddressTextField.focusRequest`)
  are gone.
- The overlay sits on `BrowserShellView` inside `WindowChromeHost`, so it
  floats above the card and the sidebar alike. The panel is `.thickMaterial`
  in `.chrome(minimum: ChromeRadius.tile)` with a shadow and no outline;
  rows use `ChromePalette.hover`/`.resting` for selected/hovered.
- `HistoryWindow` is a SwiftUI `Window` scene, which only `openWindow` can
  open, so the view handles the Show All History command before handing
  the result to the model. Settings opens through `showSettingsWindow:`.

### Also fixed
- **History search ignored punctuation.** The FTS5 sanitizer *dropped*
  non-alphanumerics, so `github.com` became the single term `githubcom*`
  and matched nothing, in the History window too. Terms now split where the
  tokenizer does.

## Key Learnings
- **`NSTextField` and inline completion:** set `stringValue` to the
  completed text and select the suffix with `currentEditor()?.selectedRange`.
  Only do it when the change *extended* the typed text (compare against the
  last typed value), never on deletion, or Backspace fights the user. Keep
  the SwiftUI binding at the typed text; the displayed text is longer until
  Tab/→ accept it.
- **⌘Return never reaches `doCommandBy`.** Catch it in
  `performKeyEquivalent` on the field subclass (key codes 36 and 76).
- **Restoring first responder after a palette:** record
  `window.firstResponder` when the field arrives and restore it in
  `viewWillMove(toWindow: nil)`. If the previous responder was a field
  editor, restore its `delegate` control instead: making an orphaned field
  editor first responder left the window drawing as inactive.
- **A SwiftUI `ScrollView` claims all offered height.** With fixed row
  heights, size the list to its content and cap it, instead of fighting
  `fixedSize`.
- **SQLite bare columns + `MAX()`:** `SELECT url, title, MAX(visited_at)`
  grouped by URL takes the title from the latest visit, which is exactly
  the one wanted.
- **Shared prefs during testing:** the user's `browser.newTabPreference`
  was already `startPage`, so the first launch didn't show the bar. Launch
  args (`-browser.newTabPreference commandBar`) override without touching
  the shared domain.

- `xcodebuild … test` runs `CoveTests` from the Cove scheme: 16 tests.
- Verified by screenshots, light and dark, top and sidebar modes: empty
  state, typing with completion/history/suggestions, ⌘L prefilled, arrow

  Tab with and without a completion, Escape, a command via Return.

  the instance is frontmost.

## Deferred
- **New Window** isn't a command: `CommandGroup(replacing: .newItem)`
  already removes File › New Window, so there is nothing to call.
- The material tints toward the page behind it (lavender over GitHub's
  navy in light mode). Legible; a solid `ChromePalette.content` fill is a
  one-line change if the user prefers it.
- No "Open in New Tab" hint on the selected row; ⌘Return is discoverable
  only from the menu-less convention.
- Suggestions and history are capped (4 and 5); nothing pages further.
- History rows show the favicon only if it has been fetched for that site
  (FaviconStore). Sites visited before favicons were cached show the globe.
